## Data Engineering Projects
 
1. **[Vendor Data Drift Reconciliation & Quality Engineering Pipeline](https://github.com/StebanJrb/Vendor-Data-Drift-Reconciliation-Quality-Engineering)**
Pandas-driven refinement of schema-drifted, multi-format vendor data — fuzzy deduplication, type reconciliation, and Great Expectations as a data contract before promotion to warehouse.
 
2. **[Distributed Clickstream & Catalog Fusion](https://github.com/StebanJrb/Distributed-Clickstream-Catalog-Fusion-PySpark)**
PySpark at scale: joining millions of e-commerce clickstream events against a nested MongoDB product catalog, with windowed session and funnel analysis.
 
3. **[Medallion Architecture Lakehouse on Databricks](https://github.com/StebanJrb/Medallion-Architecture-Lakehouse-Databricks)**
Bronze/Silver/Gold banking transaction pipeline on Databricks with Delta Lake, built around real late-arriving-data handling and point-in-time reproducible reporting.
 
4. **[Real-Time Demand Surge Detection](https://github.com/StebanJrb/Real-Time-Demand-Surge-Detection-GCP-PubSub)**
GCP Pub/Sub + Spark Structured Streaming pipeline detecting supply/demand imbalance from two independent live event streams.
 
5. **[Credit Risk Feature Store](https://github.com/StebanJrb/Credit-Risk-Feature-Store-Point-in-Time-AWS)**
Point-in-time correct feature engineering on AWS (S3, Athena, DynamoDB) — built to prevent data leakage and train/serve skew in credit risk modeling.
 
6. **[Engineering Analytics Ingestion](https://github.com/StebanJrb/Engineering-Analytics-Ingestion-GitHub-API)**
Resilient REST API ingestion from the GitHub API — rate-limit-aware backoff, cursor pagination, and idempotent upserts powering internal engineering metrics.
 
7. **[CDC — Orders System Sync](https://github.com/StebanJrb/CDC-Orders-System-Sync-Debezium-Kafka-AWS-MSK)**
Log-based Change Data Capture from PostgreSQL via Debezium and Kafka, with a documented production path to AWS MSK.
 
8. **[Cross-Team Data Observability Platform](https://github.com/StebanJrb/Cross-Team-Data-Observability-Platform)**
Cross-team data observability platform (OpenLineage + Marquez + Grafana) catching silent pipeline failures — stale tables, dropped rows, volume anomalies — before they reach exec dashboards.
 
9. **[Incremental Warehouse Migration](https://github.com/StebanJrb/Legacy-Warehouse-Migration-Northwind-dbt-Snowflake)**
Incremental warehouse migration (Postgres stored procs + MongoDB) to dbt + Snowflake, using shadow-mode parity checks and per-model feature-flagged cutover instead of a big-bang rewrite.
 
10. **[Multi-Tenant Data Platform](https://github.com/StebanJrb/Multi-Tenant-Data-Platform-AWS)**
AWS-based platform for multi-tenant isolation, PII governance, and self-service pipelines within guardrails — the capstone of this portfolio.
 
11. **[ETL Data Pipeline — Spotify](https://github.com/StebanJrb/ETL-Data-Pipeline-Spotify)**
End-to-end ETL from the Spotify API into a star schema warehouse with data quality gates.

12  **[MLOps PipeLine](https://github.com/StebanJrb/MLOps-Pipeline-CI-CD-Champion-Challenger-Drift-Monitoring)**
An incremental, sprint-scoped warehouse migration — not a one-shot rewrite. Legacy business logic spans PostgreSQL stored procedures and a MongoDB collection owned by another team
